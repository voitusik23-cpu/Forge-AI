# Forge Project Understanding & Static Project Topology v0.1

This document defines the architecture, data models, and security boundaries of the **Project Understanding** subsystem in Forge AI.

---

## 1. Purpose

The **Project Understanding** subsystem produces a deterministic, snapshot-based structural model of a target project codebase prior to planning and code modification. It extracts verifiable facts directly from disk files, package manifests, and language ASTs without executing any project code or build tools.

### Key Principles:
- **Snapshot-Based**: All structural facts and topology nodes belong to an immutable `UnderstandingSnapshot`.
- **Deterministic Facts vs. Inferences**: Direct static observations (`StructuralFact`) are strictly separated from probabilistic inferences (`InferredFact`).
- **Data-Plane Isolation**: Repository source code and manifests are treated exclusively as untrusted data.
- **Zero Execution**: Static analysis never runs `eval`, `exec`, `setup.py`, `npm`, `cargo`, or compilers.

---

## 2. Core Domain Contracts

### `StructuralFact`
An immutable, deterministic observation extracted directly from source files or configuration.
- **Attributes**: `fact_id`, `fact_type`, `source_path`, `line_start`, `line_end`, `extractor_id`, `details`.
- **Fact Types**: `MODULE_DEFINED`, `PACKAGE_DEFINED`, `SYMBOL_DECLARED`, `IMPORT_DECLARED`, `DEPENDENCY_DECLARED`, `FILE_INVENTORIED`, `MANIFEST_INVENTORIED`.
- **Rule**: Structural facts do not carry probabilistic confidence scores; their presence is verifiable against disk contents.

### `InferredFact`
A non-deterministic hypothesis or summary generated by an LLM or heuristic.
- **Attributes**: `inference_id`, `category`, `statement`, `evidence_fact_ids`, `model_id`, `trust_level=INFERRED`.
- **Rule**: Inferences must cite one or more `StructuralFact` IDs as evidence and cannot mutate or masquerade as structural facts.

### `ProjectTopology`
An immutable directed property graph connecting structural entities.
- **Nodes (`TopologyNode`)**: `FILE`, `MODULE`, `PACKAGE`, `SYMBOL`, `MANIFEST`.
- **Edges (`TopologyEdge`)**: `CONTAINS`, `IMPORTS`, `DEFINES`, `DECLARES_DEPENDENCY`, `REFERENCES`.

### `UnderstandingSnapshot`
A complete, reproducible record of repository topology at a specific point in time.
- **Attributes**: `snapshot_id`, `project_id`, `workspace_fingerprint`, `files`, `manifests`, `topology`, `facts`, `warnings`, `extractor_versions`, `parent_snapshot_id`, `created_at`.
- **Drift Detection**: `check_drift()` detects if any files on disk were modified, added, or deleted relative to the snapshot.

---

## 3. Supported Extractors

1. **Python AST Extractor (`python_ast_v1`)**:
   - Parses `.py` and `.pyi` files using standard library `ast.parse()`.
   - Extracts modules, packages (`__init__.py`), direct imports, `from ... import`, classes, base classes, methods, async functions, parameters, and top-level constants.
2. **Manifest Extractor (`manifest_static_v1`)**:
   - Statically inspects package declarations in `requirements.txt`, `pyproject.toml`, `package.json`, `package-lock.json`, `go.mod`, `Cargo.toml`, `pom.xml`, and `*.csproj`.
3. **Generic Extractor (`generic_regex_v1`)**:
   - Bounded line-based regex extraction for JavaScript, TypeScript, Go, Java, C#, and Rust.

---

## 4. Security & Resource Boundaries

- **Filesystem Containment**: All scans are constrained strictly within `Workspace.root` using `Workspace.normalize_relative_path` and `resolve_target`. Symlinks pointing outside the workspace are skipped.
- **Secret Exclusion**: `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `credentials.json`, and `service_account.json` are excluded from content indexing.
- **Resource Limits (`ScanLimits`)**:
  - `max_file_size_bytes`: default 512 KB (oversized files skipped from AST extraction).
  - `max_total_bytes`: default 50 MB.
  - `max_file_count`: default 5,000 files.
- **Vendor & Cache Directory Exclusion**: `.git`, `__pycache__`, `node_modules`, `vendor`, `.venv`, `venv`, `dist`, `build`, `.idea`, `.vscode` are ignored automatically.
- **Fault Tolerance**: Syntax errors in target files produce `ScanWarning` records and never crash the scan.

---

## 5. Future Subsystem Integrations

- **Discovery**: Seeds known codebase modules, packages, and manifests into requirements gathering.
- **Planner**: Uses topology dependency graphs to order implementation tasks.
- **Reviewer**: Evaluates proposed pull requests against architectural constraints.
- **Diff & Blast Radius**: Calculates dependency closures (`affected_modules`) for modified files.

# Понимание проекта и статическая топология Forge v0.1 — русская версия

Этот документ определяет архитектуру, модели данных и границы безопасности подсистемы **Project Understanding** в Forge AI.

---

## 1. Назначение

Подсистема **Project Understanding** формирует детерминированную структурную модель кодовой базы на основе снимков (snapshots) до начала планирования и изменения кода. Она извлекает проверяемые факты напрямую из файлов на диске, манифестов пакетов и AST языков программирования без выполнения кода проекта и инструментов сборки.

### Ключевые принципы:
- **Основано на снимках**: Все структурные факты и узлы топологии принадлежат неизменяемому объекту `UnderstandingSnapshot`.
- **Детерминированные факты против выводов**: Прямые статические наблюдения (`StructuralFact`) строго отделены от вероятностных выводов (`InferredFact`).
- **Изоляция плоскости данных**: Исходный код и манифесты репозитория рассматриваются исключительно как непроверенные данные.
- **Нулевое выполнение**: Статический анализ никогда не запускает `eval`, `exec`, `setup.py`, `npm`, `cargo` или компиляторы.

---

## 2. Основные доменные контракты

### `StructuralFact`
Неизменяемое детерминированное наблюдение, извлечённое напрямую из исходных файлов или конфигурации.
- **Атрибуты**: `fact_id`, `fact_type`, `source_path`, `line_start`, `line_end`, `extractor_id`, `details`.
- **Типы фактов**: `MODULE_DEFINED`, `PACKAGE_DEFINED`, `SYMBOL_DECLARED`, `IMPORT_DECLARED`, `DEPENDENCY_DECLARED`, `FILE_INVENTORIED`, `MANIFEST_INVENTORIED`.
- **Правило**: Структурные факты не содержат вероятностных оценок уверенности (confidence); их наличие строго проверяемо по содержимому диска.

### `InferredFact`
Недетерминированная гипотеза или резюме, сгенерированное LLM или эвристикой.
- **Атрибуты**: `inference_id`, `category`, `statement`, `evidence_fact_ids`, `model_id`, `trust_level=INFERRED`.
- **Правило**: Выводы обязаны ссылаться на идентификаторы одного или нескольких `StructuralFact` в качестве доказательств и не могут маскироваться под структурные факты.

### `ProjectTopology`
Неизменяемый ориентированный граф свойств, связывающий структурные сущности.
- **Узлы (`TopologyNode`)**: `FILE`, `MODULE`, `PACKAGE`, `SYMBOL`, `MANIFEST`.
- **Рёбра (`TopologyEdge`)**: `CONTAINS`, `IMPORTS`, `DEFINES`, `DECLARES_DEPENDENCY`, `REFERENCES`.

### `UnderstandingSnapshot`
Полный воспроизводимый слепок топологии репозитория на определённый момент времени.
- **Атрибуты**: `snapshot_id`, `project_id`, `workspace_fingerprint`, `files`, `manifests`, `topology`, `facts`, `warnings`, `extractor_versions`, `parent_snapshot_id`, `created_at`.
- **Обнаружение дрейфа**: Метод `check_drift()` определяет, были ли изменены, добавлены или удалены файлы на диске относительно снимка.

---

## 3. Поддерживаемые экстракторы

1. **Экстрактор Python AST (`python_ast_v1`)**:
   - Парсит файлы `.py` и `.pyi` с помощью стандартной библиотеки `ast.parse()`.
   - Извлекает модули, пакеты (`__init__.py`), прямые импорты, импорты `from ... import`, классы, базовые классы, методы, асинхронные функции, параметры и константы верхнего уровня.
2. **Экстрактор манифестов (`manifest_static_v1`)**:
   - Статически анализирует объявленные зависимости в `requirements.txt`, `pyproject.toml`, `package.json`, `package-lock.json`, `go.mod`, `Cargo.toml`, `pom.xml` и `*.csproj`.
3. **Универсальный экстрактор (`generic_regex_v1`)**:
   - Ограниченное построчное регулярное извлечение для JavaScript, TypeScript, Go, Java, C# и Rust.

---

## 4. Границы безопасности и ресурсов

- **Ограничение файловой системы**: Все сканирования строго ограничены `Workspace.root` с помощью `Workspace.normalize_relative_path` и `resolve_target`. Символические ссылки, ведущие за пределы рабочей области, пропускаются.
- **Исключение секретов**: Файлы `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `credentials.json` и `service_account.json` исключаются из индексации содержимого.
- **Лимиты ресурсов (`ScanLimits`)**:
  - `max_file_size_bytes`: по умолчанию 512 КБ (слишком большие файлы пропускаются при AST-анализе).
  - `max_total_bytes`: по умолчанию 50 МБ.
  - `max_file_count`: по умолчанию 5 000 файлов.
- **Исключение каталогов кэша и зависимостей**: `.git`, `__pycache__`, `node_modules`, `vendor`, `.venv`, `venv`, `dist`, `build`, `.idea`, `.vscode` автоматически игнорируются.
- **Устойчивость к ошибкам**: Синтаксические ошибки в файлах проекта формируют записи `ScanWarning` и не прерывают сканирование.

---

## 5. Будущая интеграция с подсистемами

- **Discovery**: Передаёт известные модули, пакеты и манифесты кодовой базы в процесс сбора требований.
- **Planner**: Использует граф зависимостей топологии для упорядочивания задач реализации.
- **Reviewer**: Проверяет предлагаемые изменения на соответствие архитектурным инвариантам.
- **Diff & Blast Radius**: Рассчитывает замыкание зависимостей (`affected_modules`) для изменённых файлов.
